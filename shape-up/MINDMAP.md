# Shape Up (Basecamp, Ryan Singer)

## Core idea

- Fixed time, variable scope
- Appetite, not estimate — "start with a number, end with a design"
- Target one risk: **not shipping on time**
- Virtuous circle: autonomy ← better shaping ← less managing

## Part 1 — Shaping

### Ch 2 · Principles of Shaping

- Right level of abstraction
  - Wireframes → too concrete
  - Words → too abstract
- Shaped work is…
  - Rough
  - Solved
  - Bounded
- Who shapes: generalists, technically literate, strategic
- Two tracks: shaping ∥ building
- Case: Dot Grid Calendar — "which tenth of a calendar?"

### Ch 3 · Set Boundaries

- Appetite
  - Small Batch: 1–2 weeks
  - Big Batch: 6 weeks
- "Good" is relative — hot dog vs. ten-course dinner
- Raw ideas → soft "no": *"Interesting. Maybe some day."*
- Narrow the problem
  - Ask **when**, not what — chalkboard-calendar story
  - "See free spaces" ≠ "everything a calendar does"
- Beware grab-bags & "2.0" projects

### Ch 4 · Find the Elements

- Move fast, right people, right detail
- Breadboarding
  - Places / Affordances / Connection lines
  - Words, not pictures
- Fat marker sketches — detail impossible
- Output = elements, not a spec
- "Boundaries and rules of a game"
- No conveyor belt — can still walk away

### Ch 5 · Risks & Rabbit Holes

- Goal: thin-tailed distribution
- Walk the use case in slow motion
- Patch holes up front (To-Do Groups: completed items)
- Declare out of bounds
- Cut back non-essentials
- Ask experts: "possible **in 6 weeks**?"
- Keep the clay wet

### Ch 6 · Write the Pitch

- 5 ingredients
  1. Problem — one specific story
  2. Appetite
  3. Solution — help them *see* it
  4. Rabbit holes
  5. No-gos
- Embedded / annotated sketches
- Async first: post, comment, then bet

## Part 2 — Betting

### Ch 7 · Bets, Not Backlogs

- No backlogs — no grooming, no guilt
- A few potential bets per cycle
- Decentralized lists per department
- Important ideas come back

### Ch 8 · The Betting Table

- 6-week cycles (sprints too short/costly)
- 2-week cool-down
- Teams: 1 designer + 1–2 programmers
- Bet = payout + commitment + capped downside
- Uninterrupted time — "losing a day can kill a week"
- Circuit breaker: no default extensions
- Bugs: cool-down / betting table / bug smash
- Clean slate every cycle

### Ch 9 · Place Your Bets

- Existing product → standard cycle
- New product phases
  - R&D: seniors spike, nothing ships
  - Production: ship = merge to main
  - Cleanup: free-for-all, final cut
  - Case: HEY (1y R&D → 1y production → 2 cleanup)
- Betting questions
  - Problem matter? Appetite right?
  - Solution attractive? Right time? Right people?
- Kick-off message

## Part 3 — Building

### Ch 10 · Hand Over Responsibility

- Assign projects, not tasks
- Done = deployed in-cycle
- Respect the quiet orientation days (~3)
- Imagined vs. discovered tasks

### Ch 11 · Get One Piece Done

- Integrate one vertical slice in week 1
- Case: visibility toggle (Clients in Projects)
- Affordances before pixel-perfect
- Program just enough (stubs, HTTPAuth)
- Start in the middle: core + small + novel

### Ch 12 · Map the Scopes

- Organize by structure, not person
- Scope = independently finishable slice
- Scopes = language of the project
- Walk the territory before drawing the map
- Right scopes: see the whole, flowing talk, obvious buckets
- Wrong scopes: unclear "done", junk-drawer names, too big
- Layer cakes / Icebergs / Chowder (≤3–5)
- `~` marks nice-to-haves

### Ch 13 · Show Progress

- To-do lists grow — counts mislead
- Estimates hide uncertainty
- The Hill
  - Uphill = figuring out
  - Top = "now I know"
  - Downhill = execution
- Dots per scope; history = killer feature
- Stuck dot = raised hand, no words needed
- Refactor stuck scopes (Notify → 3 parts)
- Build your way uphill (hands, not head)
- Scariest work first — inverted pyramid

### Ch 14 · Decide When to Stop

- Compare down to baseline, not up to ideal
- Scope grows like grass — keep hammering
- Cutting scope ≠ lowering quality
- Hammer questions: must-have? ship without? who sees it?
- QA = level-up for edges, not a gate
- Extend only if: true must-haves **and** all downhill

### Ch 15 · Move On

- Let the storm pass
- Stay debt-free — gentle "no"
- Feedback → raw ideas → shape again (full circle)

## Appendices

### Implement in Basecamp

- Product Strategy team → pitches
- Project per bet, list per scope
- Hill chart per list

### Adjust to Your Size

- Truths are scale-free; practices aren't
- Tiny team: wing it, alternate hats
- Bigger: specialize, formal cycles

### How to Begin

- A: one 6-week experiment
- B: start with shaping
- C: start with cycles
- Fix shipping first
- Judge the macro outcome
